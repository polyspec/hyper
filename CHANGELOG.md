- The CSRF protection no longer depends on the application (H1). Every response carries `csrf` as a masked value of the session token: 32 random bytes drawn for that response followed by those bytes XOR the token, as 128 hexadecimal digits, and an action or a save of a kept value is accepted only with a masked value of the token (HY-24); `conformance/csrf.json` holds the cases that both servers pass. An action calls `renewSession()` of its reply at sign-in and sign-out; the server moves the session to a new identifier, deletes the old one and creates a new token, and a loader that calls it fails with 500 (HY-72). `Reply::cacheControl` and `reply.cacheControl` refuse a value without `private` or `no-store` or with `public` or `s-maxage`, because a shared cache would give the token of one visitor to another (HY-52). The `ETag` of a JSON response is weak and hashes the body with the masked token replaced by the session token, so the mask does not prevent a 304 and a renewed session has another tag (HY-53). A stored token that is not 64 lowercase hexadecimal digits is replaced. `CsrfTest`, `ReplyTest`, `NativeSessionTest`, `AppTest`, `csrf.test.ts`, `sessions.test.ts` and `app.test.ts` failed before the change; `make server-parity` compares the masked tokens with the weak tags.
