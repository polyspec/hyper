# 성능 측정

[English](benchmark.md).

`make bench`는 게시판 예제를 서버와 브라우저에서 측정한다. 결과는 보고용이다. 시간은 기계와 그 부하에 따라 달라지므로 통과나 실패를 판정하지 않는다. 측정은 한가한 기계에서 실행한다. 다른 바쁜 프로세스는 중앙값보다 평균과 p95를 더 크게 바꾼다.

| 타깃 | 스크립트 | 측정 대상 |
|---|---|---|
| `make bench-server` | `scripts/bench-server.php --app <directory> --iterations <n>` | 네트워크 없이 요청 종류별 `App::handle`, 그리고 10, 100, 1,000행에서 `board/rows.tpl` 렌더, `Bind::value`, `json_encode` 비용 |
| `make bench-browser` | `scripts/bench-browser.mjs --ssr <port> --edge <port> --api <port> --runs <n>` | SSR과 CSR 첫 화면, 영역 이동, 10, 100, 1,000행에서 `hy-set` 변경 1회의 시간과 메인 스레드 부하, 템플릿 엔진 단독, 반복 이동 중 메모리, 템플릿 로드, 전송 바이트 |

두 스크립트는 `examples/board/var/` 아래에 자체 데이터베이스를 만들고 끝나면 지운다. `bench-browser`는 포트 8085~8087에서 `scripts/serve-demo.mjs`를 실행한다.

## 방법

- **서버:** 요청마다 20회 예열한 뒤 지정한 횟수만큼 한 프로세스 안에서 메모리 세션으로 실행한다. 시간은 `App::handle` 앞뒤의 `hrtime`이다. 라우팅, SQLite 로더, 렌더, 인코딩을 포함하고 네트워크와 PHP 시작은 제외한다.
- **첫 화면:** 페이지 로드 전에 추가한 `MutationObserver`가 목록 제목 `게시판`이 나타난 시각을 내비게이션 시작부터 기록한다. 매 회 새 브라우저 컨텍스트를 쓰므로 캐시가 없다.
- **영역 이동:** 글쓰기 링크 클릭부터 제목 `글쓰기`가 나타날 때까지의 시간이다.
- **`hy-set` 변경:** 호출부터 스왑이 끝날 때까지의 `window.hyper.set('rows', 'sort', …)` 시간이다. 클릭 뒤와 같게 변경마다 페이지가 프레임 하나를 렌더한다.
- **메인 스레드 부하:** 같은 변경을 Chromium 트레이스로 기록한다. 스크립트는 렌더러 메인 스레드의 모든 이벤트의 자기 시간을 종류별로 합한다. 그래서 스크립트 안에서 강제된 스타일 계산은 스타일로 센다. 값은 변경 1회당이며 그 뒤의 프레임을 포함한다. 50 ms를 넘는 작업은 입력을 지연시킨다.
- **메모리:** 링크를 클릭해 `/board` → `/board/create` → `/board/<id>` → `/board`를 200회 반복한다. 50회마다 가비지 컬렉션을 강제한 뒤 JavaScript 힙, DOM 노드, 이벤트 리스너, 문서 수를 기록한다.

## 결과 해석

- 영역 JSON 응답의 서버 비용은 문서의 약 7분의 1이다. 렌더를 브라우저가 하기 때문이다.
- SSR 첫 화면은 CSR 첫 화면보다 약 2배 빨리 나타난다. CSR은 셸을 받은 뒤 JSON과 템플릿 파일을 요청하기 때문이다. 이 결과는 권장 배포를 뒷받침한다.
- 100행까지의 `hy-set` 변경은 16 ms 프레임 하나 안에 끝난다. 1,000행에서는 변경에 25 ms가 걸린다. 위 실행에는 50 ms를 넘는 작업이 없었지만, 같은 날 반복 실행에서는 변경 15회 중 137 ms 작업이 1회 나왔고 대부분 페인트였다. 따라서 그 크기의 목록은 입력을 지연시킬 수 있다. 변경 시간 중 템플릿 엔진은 3 ms이고 나머지는 DOM 갱신(엔진 밖의 스크립트, 레이아웃, 스타일)이다. 그 크기의 목록은 페이지로 나눈다.
- DOM 노드와 이벤트 리스너는 200회 이동 동안 일정하다. 따라서 교체된 영역은 노드나 리스너를 남기지 않는다. JavaScript 힙은 브라우저가 템플릿을 로드해 캐시하고 코드를 컴파일하는 처음 50회 동안 늘고, 150회와 200회 사이에는 30 KB 미만 늘어난다.
- PHP는 1,000행을 브라우저 엔진보다 약 6배 느리게 렌더한다. PHP는 직접 요청만 렌더하므로 이 차이는 이동이 아니라 첫 문서에만 영향을 준다.
