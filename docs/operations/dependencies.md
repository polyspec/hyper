Every dependency uses the latest stable release that supports the declared runtime range: Node.js 26 and PHP 8.2. An exact pin records its reason and the condition that removes it.

| Dependency | Version | Kind | Reason | Removal condition |
|---|---|---|---|---|
| Node.js, npm, PHP, Composer, make, Rust | `.node-version` 26.8.1, `packageManager` npm 12.2.0, `config/toolchain.json` PHP 8.5.10, Composer 2.10.3 and make 3.81, `rust-toolchain.toml` of the template commit, exact | toolchain | A build or a check gives the same result only with the same tools (HY-81); npm 12 prints `npm pack --json` differently from npm 11, and the native extension of main was built with Rust 1.98.0 while the template repository pins 1.98.1. | None: a new release becomes a commit that changes the pin. |
| `htmx.org` | `4.0.0` exact | runtime, bundled into the client script | The region protocol uses htmx 4 hooks, request context fields and swap behavior that were verified against the 4.0.0 source. npm tags 4.0.0 as `next` and keeps 2.x as `latest`, so an unpinned range would select htmx 2. | npm tags an htmx 4 release as `latest`; then use a `^4` range and rerun `make check`. |
| `@playwright/test`, `@types/node`, `esbuild`, `typescript`, `vitest` | exact | development | The root package pins exact development tool versions so that `npm ci` installs the same tools. | Update to each latest stable release and rerun `make check`. |

| `@polyspec/hyper` in `@polyspec/hyper-server` | `0.0.1` exact | runtime | The Node server renders with the browser package of the same repository, so it requires that exact version; the root package overrides it with the copy of `packages/hyper-js` (HY-79). | The packages are published and released together under one version range. |
| `@polyspec/template`, `polyspec/template` | local path, named branch | runtime | The template packages are not published, so they are used from the declared copy `var/products/template` that `make template` writes from `../template` (HY-78). The copy is the commit at the head of the branch that `config/template.json` names, so the same tree uses the same template branch on every machine; a new commit of the branch reaches this repository when `config/template.json` changes (HY-80). npm installs `@polyspec/template` as a copy (`install-links=true` in `.npmrc`, a root dependency and an override for the packages of the workspace), because a link would read the template checkout, whose build empties `dist`. Composer copies `polyspec/template` (`symlink: false`, `reference: config`, version `dev-main`), so the lock files do not change with the content of the copy or with the branch of this repository. Neither package manager installs a path package again while its version and reference stay the same, so `make template` publishes the changed files into the npm copy and both Composer copies with `scripts/publish.mjs` and fails with the install command when the dependencies of the package changed (HY-82). | The template packages are published to npm and Packagist. |
