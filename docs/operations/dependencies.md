## Multipart parsers

Each server reads a `multipart/form-data` body with its own parser, which must meet HY-57, HY-113 and HY-42. This section records the check of the maintained parser of each ecosystem against those rules, by its source at the version named here (H26.3). The check read the packages; it installed none of them, so no lock and no review record changed. No candidate meets the rules, so each server keeps its parser. The other PHP packages were not checked.

| Server | Current parser | Candidate and version | Result and reason | Condition for a replacement |
|---|---|---|---|---|
| PHP | `Multipart::read` in `packages/server/php/src/Multipart.php`, called by `Fields.php` | `riverline/multipart-parser` 2.2.2 (MIT, released 2026-01-15) | Kept. The body of a part is decoded by its `Content-Transfer-Encoding` (`src/StreamedPart.php`, `getBody`, base64 and quoted-printable), while HY-57 reads the content of the part as it is. Header values are decoded as MIME words (`mb_decode_mimeheader`, line 107). The options of `Content-Disposition` are split at every `;` (`parseHeaderContent`, line 394), so a quoted filename that holds a `;` is cut, and a `filename*` value replaces the filename (line 403), which HY-113 forbids (no further decoding). | A version that keeps the content, the header values and the options of a part as written. |
| Python | `polyspec/hyper/_fields.py`, `_multipart` | `python-multipart` 0.0.32 (Apache-2.0, released 2026-06-04) | Kept. It meets HY-57 and HY-113 except one step: `parse_options_header` (`python_multipart/multipart.py`, lines 217 to 219) replaces a filename that starts with `C:\` or `\\` by its last segment, which HY-113 forbids. | A version without that step, or an option that keeps the filename as written. Then the parser is replaced in a sub-row of H26.3. |
| Node | `packages/server/ts/src/form.ts` | `busboy` 1.6.0 (MIT) | Kept. Four steps differ from HY-57, HY-113 and HY-42: `filename*` takes precedence over `filename` (`lib/types/multipart.js`, lines 316 to 319); the filename is cut to its basename unless `preservePath` is set (lines 321 to 322); a part with no filename and the type `application/octet-stream` is a file (line 337), while HY-57 makes it a value; the content of a part is decoded by its `Content-Transfer-Encoding` (lines 335 and 363); and a field value is decoded by a `TextDecoder` that replaces invalid UTF-8 (`lib/utils.js`, lines 465 to 468) instead of refusing it under HY-42. | A version that keeps the filename and the content of a part as written and refuses invalid UTF-8 in a field value. |

PHP 8.4's native `request_parse_body()` was also considered and refused: it nests bracketed names like `$_POST`, which HY-57 refuses.
