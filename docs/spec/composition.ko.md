# 화면 구성

[English](composition.md).

이 문서는 화면의 각 부분이 어떤 장치를 사용하는지 정의한다. 부분은 쓰이는 곳마다 무엇이 다른지로 고른다. 아래의 모든 장치는 template 언어와 영역 프로토콜이 이미 제공한다. 새 장치는 부분이 어느 장치에도 맞지 않을 때만 추가한다.

## 장치

| 다른 것 | 장치 | 예 |
|---|---|---|
| 모양 외에는 없음 | HTML 요소와 CSS 클래스 | 카드, 패널, 버튼, 표 틀 |
| 모양과 데이터 | 격리된 스코프를 가진 블록 `{# path name:value}` | 게시글 행, 페이저, 필드 오류 |
| 모양, 데이터, 독립 갱신 | 영역: 매니페스트 항목, 로더, 주제 | 레프트 메뉴, 알림 배지, 위젯 |
| 브라우저에서 바뀌는 모양과 데이터 | `hy-set`으로 영역 데이터를 바꾸는 라우트 영역 | 정렬되는 목록, 닫히는 공지 |

- **HC-1** 쓰이는 곳마다 내용만 다른 부분은 쓰는 곳에서 CSS 클래스를 붙인 HTML로 작성한다. 공통 모양은 스타일시트에 둔다. 감싸기만 하는 부분에는 템플릿 추상화를 두지 않는다.
- **HC-2** 데이터를 받는 부분은 블록 태그 `{# path name:value}`로 렌더하는 템플릿 파일이다. 이 부분은 루트 데이터와 태그 인자만 읽는다(template 런타임 규칙 RT-26). 호출한 쪽의 지역 변수는 읽지 않는다.
- **HC-3** 자기 데이터를 불러오고 페이지와 별도로 바뀌는 부분은 영역이다(HY-1 ~ HY-3). 영역은 사용하는 주제를 선언하고, 그 주제가 바뀌면 서버가 영역을 다시 렌더한다(HY-18, HY-19).
- **HC-4** 매니페스트 영역, 제목, 데이터를 배치하는 템플릿은 레이아웃 하나뿐이다. 라우트 템플릿은 페이지 영역을 채우며, 자기 라우트의 라우트 영역만 배치한다.
- **HC-5** HTML이 제공하는 상호작용은 HTML 요소를 사용한다. 모달은 `<dialog>`, 접기는 `<details>`, 입력은 `<form>`을 쓴다. 이동과 폼 전송은 일반 `<a href>`와 `<form method action>`을 쓴다.
- **HC-6** `hx-*` 속성은 레이아웃에만 둔다. 페이지, 블록, 영역 템플릿에는 `hx-*` 속성을 두지 않는다. htmx는 레이아웃이 상속하는 속성으로 이 템플릿들에 적용된다(HY-3, HY-21). 레이아웃이 아닌 템플릿에 `hx-` 속성이 있으면 `make templates-check`가 실패한다.
- **HC-7** 페이지 중 요청 없이 브라우저에서 바뀌는 부분은 라우트 영역이다(HY-30). 그 화면 상태(예: 정렬 순서, 펼친 패널)는 영역 데이터다. 요소는 `hy-set`(HY-36)으로, 코드는 `set`(HY-33)으로 이를 바꾼다. 어느 쪽도 영역 데이터 밖에 상태를 두지 않는다. 새로고침 후에도 남아야 하는 값은 유지 경로(HY-37)다. 첫 SSR 문서가 그 값을 보여줘야 하면 `server`나 `cookie`를, 브라우저에만 남으면 되면 `localStorage`나 `sessionStorage`를 쓴다.

## 예

```
<section class="card">
<h2>최근 글</h2>
<ul>{@ p = posts}<li>{# /board/row.tpl p}</li>{/}</ul>
</section>
```

카드는 `card` 클래스를 가진 HTML이다(HC-1). 각 행은 `p`를 받는 블록이다(HC-2). 이 목록을 페이지 이동 없이 갱신해야 한다면, 로더와 `posts` 주제를 가진 영역이 된다(HC-3).
